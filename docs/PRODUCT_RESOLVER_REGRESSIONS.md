The live Google response for both H&M queries was HTTP 200 HTML containing only a JavaScript enablement shell. Brave returned 429, while the matching foreign H&M page returned Akamai 403. The fallback therefore used Bing's exact-article web results for product identity and public DuckDuckGo image results whose destination was the same H&M article and whose image URL was H&M-hosted. A foreign H&M page's price was not used. Both exact pasted links were submitted through Cura's Vite-proxied `/api/extract-product` route after restarting the local API with resolver version 4; the image proxy returned `200 image/jpeg` for both selected images. No CAPTCHA or access-control bypass was attempted. Canadian price remains unavailable because no same-article Canadian CAD offer was verified.

The local automatic-import counter is browser `localStorage` key `cura-import-quota-v1`, loaded and saved by `src/App.tsx`. The CLI cannot edit the current browser origin's storage. To reset only the active local testing counters, run this single line in that Cura tab's DevTools console and reload:

```js
const k='cura-import-quota-v1'; const q=JSON.parse(localStorage.getItem(k)||'{}'); localStorage.setItem(k,JSON.stringify({...q,guestUsed:0,monthlyUsed:0})); location.reload();
```

This retains the current tier, reward grants, and imported-product keys. It changes only the open browser origin's quota record and does not change production caps.
